# Wordpress Plugin to select images from Dropbox and import into NGG

A WordPress admin plugin: pick photos from a Dropbox folder by date range, select them in a
full-width grid, and turn the selection into a NextGEN Gallery.

* Folder (type or *Browse...*), FROM date, TO date, optional *include subfolders*
* Only after a valid selection the plugin queries Dropbox and shows thumbnails of the
  photos in that date range
* Grid with a selectable number of columns, full page width; click selects, Shift+click
  selects a range
* Right side panel listing the selected pictures (name, 100 px preview, top to bottom),
  a gallery name field and a **Create NGG gallery** button with an in-page confirmation
* On confirm every selected picture is 1) downloaded from Dropbox, 2) reduced to max 2048 px
  and max 500 KB, 3) registered in a new NextGEN gallery with thumbnails generated

## Layout

```
plugin/sew-dropbox-ngg-picker/     the WordPress plugin
  sew-dropbox-ngg-picker.php       menu pages, settings, OAuth callback, AJAX endpoints, self-test
  includes/                        Dropbox client, image processor, NextGEN importer
  admin/                           picker.js / picker.css
  sew-dnp-config.php               generated by the deploy from .env, gitignored (app key/secret)
deploy/
  deploy.py                        FTP upload with backup, health check, rollback and activation
  ftp.py                           FTP/FTPS helper (standard library only)
.env.example                       all settings, documented
```

## Setup

### 1. Dropbox app

Create an app at [dropbox.com/developers/apps](https://www.dropbox.com/developers/apps)
(scoped access, full Dropbox).

* **Permissions** tab: enable `account_info.read`, `files.metadata.read`,
  `files.content.read`, then *Submit*. Tokens issued before this do not carry the scopes.
* **Settings** tab: add `https://<your site>/oauth/dropbox/callback` as redirect URI.

### 2. Configure

```bash
cp .env.example .env      # then fill it in
```

`.env` holds the Dropbox `App_key` / `App_secret` and the WordPress + FTP credentials
needed to deploy. The credentials can be given in two ways:

* **a)** directly in `.env`: `WP_URL`, `WP_USER`, `WP_PWD` (an Application Password),
  `FTP_IP`, `FTP_USER`, `FTP_PWD`, `FTP_FOLDER`
* **b)** `SUB_ENV_PATH=<directory or .env file>` of another project that already has them;
  it only fills in keys that `.env` leaves empty

### 3. Deploy

```bash
python3 deploy/deploy.py            # upload, health check, activate
python3 deploy/deploy.py --check    # site health and plugin state only
python3 deploy/deploy.py --no-activate
```

Plain Python 3, no packages. The Dropbox credentials are rendered into the plugin's
`sew-dnp-config.php` on the way up and never committed. Remote files are backed up to
`deploy/.remote-backup/<timestamp>/`; if the live site shows a fatal error afterwards the
previous version is restored. Activation uses the WordPress REST API with the Application
Password; if that is not possible, activate the plugin in wp-admin.

Without `App_key` / `App_secret` in `.env` the plugin's settings page offers fields for them
instead.

### 4. Connect

wp-admin -> **Dropbox Picker -> Settings** -> *Connect Dropbox*. Approve on Dropbox and you
land back on the picker. The plugin stores a refresh token and renews the short-lived access
token itself. The settings page also shows diagnostics and an import **self-test** that runs
resize + NextGEN import + thumbnails + cleanup on an existing gallery photo, without Dropbox.

## Usage

wp-admin -> **Dropbox Picker**

1. Folder, FROM and TO. *Load pictures* enables only when all three are valid.
2. The plugin runs a Dropbox **search** (`after:` / `before:` operators, image category,
   restricted to the folder), so Dropbox does the date filtering. The exact range is then
   applied in the blog's timezone on the file's Dropbox time. Non-image files are counted
   and skipped. Dropbox's search index lags a little for files uploaded seconds ago.
3. Choose 2-10 columns, select pictures (Shift+click for ranges), enter a gallery name. The
   folder is the German-aware slug of the name, e.g. `wp-content/gallery/hot-8-brass-band-live`.
   Typing also searches the **existing** NextGEN galleries; pick one from the suggestions and it
   becomes a tag with the notice "You will add pictures to an existing gallery, not create a new
   one". The button then reads *Add to NGG gallery*, new files continue the numbering of the
   folder and only the added pictures get thumbnails. The tag's × switches back to creating a
   new gallery.
4. *Create NGG gallery* -> confirm. The import runs image by image, two in parallel:
   download original, rotate by EXIF, resize to <= 2048 px, lower JPEG quality until
   <= 500 KB, strip EXIF (no GPS on the blog). Files are named `NNN-<original>.jpg` so the
   gallery order is chronological. Finally the folder is registered with NextGEN and the
   thumbnails are built. The result shows the NextGEN link and the shortcode.

## Notes

* NextGEN loads its storage module only in an admin context, which `admin-ajax.php`
  provides; that is why the import runs over AJAX and not the REST API.
* The OAuth callback URL is intercepted on `init` before WordPress routes the request, so
  it works without pretty permalinks. It requires a logged-in administrator in the same
  browser and a matching `state`.
* With GD as image editor, photos too large for `memory_limit` are fetched as Dropbox's own
  2048x1536 rendition instead of the original; Imagick handles originals directly.
